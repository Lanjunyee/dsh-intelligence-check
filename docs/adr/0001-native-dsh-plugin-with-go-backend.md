# 使用 DeepSeek Harness 原生插件承接现有 Go 检测后端

迁移以 DeepSeek Harness 为唯一宿主，使用其原生插件接口管理现有 Go 后端的启动与退出，保留 SQLite、检测功能与独立网页控制台。相较于将后端和界面重写为宿主内的 TypeScript 与 React 组件，这一选择优先复用已有功能，同时继续承担多平台二进制分发与子进程生命周期管理。

产品定位改为主动测试与报告：检测结果不阻断业务模型请求，不再保留 Magpie 的请求门禁集成。保留题库、手动检测、历史、人工评审、HTML/SVG 预览及 ModelTrace；旧版数据原样保留，首版不导入。

自动检测默认关闭。使用者开启后，仅对明确加入监测的模型定时执行 milk 基础题，默认间隔 15 分钟，可调整；其余质量题与 ModelTrace 保留手动运行。检测仅在宿主及插件后台运行期间执行，不依赖业务对话触发。

配置、历史、人工评审和后台实例按 profile 隔离，同一 profile 的不同会话共享。

检测目标使用宿主配置的 provider 与 model 组合标识。原生插件通过公开的模型目录 API 与 `ctx.llm.stream()` 代理 Go 后端的检测请求，复用宿主凭据，不再单独配置 Magpie 网关或复制 API key。插件提供打开独立网页控制台的入口，具体入口形式按宿主公开接口实现。
