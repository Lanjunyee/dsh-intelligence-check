# 使用 DSH 原生检测页面与用户级共享检测状态

本决策取代 [ADR 0001](0001-native-dsh-plugin-with-go-backend.md) 中的独立网页控制台、按 profile 隔离及由各宿主实例分别启动后台的规定，其余领域行为继续适用。当前实现实际上按 DSH profile 隔离，而非按工作目录隔离；新版将同一用户、同一台机器的检测配置、监测目标、检测记录、人工评审及后台统一共享，避免切换工作目录或 profile 后出现不同的检测状态和重复自动检测。

删除 `/dsh-intelligence-check` 命令入口，在 DSH 全局侧边栏提供“模型质量检测”入口，在主区域展示原生检测页面。继续复用 Go 检测后端，保留题库、手动检测、自动检测、历史、人工评审、导出、HTML/SVG 作品预览和 ModelTrace。相较于复用独立网页，此方案承担界面迁移成本，以融入 DSH 的导航、主题及布局。

共享后台由 DSH 桌面应用管理，统一使用桌面应用配置的 provider、模型与凭据；单独启动 CLI 不启动后台。多个 profile 不分别运行自动检测；切换页面或关闭检测面板不停止检测，退出 DSH 桌面应用时必须关闭插件后台。自动检测仍默认关闭，其检测范围与调度行为沿用 ADR 0001。

插件尚未对外投入使用，新版从空数据开始，不迁移或自动合并旧 profile 数据，也不要求为迁移制作备份。此决定不授权删除已有旧数据。
